Project Overview

The Enterprise Financial Services Design System was built to solve a growing crisis of inconsistency at Credit One Bank. With no shared UI foundation, the IT team had organically produced 68 unique "primary" buttons across 10 internal applications — a symptom of deeper fragmentation. Developers were spending over half their time recreating basic components, while users struggled to recognize familiar actions across platforms.

This 6-month initiative delivered a unified component library built on atomic design principles. By creating desktop-optimized atoms, molecules, and organisms, the system enabled rapid application development while maintaining consistency and allowing for unique application identities. The result: 70% faster UI development, 95% component adoption, and 100% WCAG AA compliance.

The Challenge

Credit One Bank's IT team had never used a design system. Developers made real-time UI decisions — resulting in 68 unique "primary" buttons across 10 internal apps.

Three Core Problems

  • Users: Same action, different look — trust eroded silently.
  • Engineers: 60% of time rebuilding components from scratch.
  • Onboarding: New hires learned 12+ undocumented patterns.

Audit: 68 buttons, 42 text fields, 19 alert styles — all incompatible.

Research & Discovery

We conducted a comprehensive audit of existing products and interviewed 15+ stakeholders across design, engineering, and product teams to understand pain points and requirements.

User Interviews

Spoke with designers, developers, and product managers to understand their workflow challenges and component needs. Key insight: Teams wanted flexible, reusable components that could adapt to different application contexts without losing consistency.

Component Audit

Catalogued 200+ unique components across 8 products. Found massive duplication with slight variations, indicating need for standardization at the foundational level while maintaining flexibility for application-specific implementations.

Atomic Design Approach

Rather than creating rigid, application-specific components, I architected a flexible system using atomic design principles. This approach created desktop-optimized atoms, molecules, and organisms that could be combined and customized across different applications while maintaining visual consistency.

System Philosophy

By building from the ground up with atoms (basic UI elements), molecules (simple component groups), and organisms (complex UI sections), each application could maintain its unique identity while sharing a common design language. This modular approach meant minimal modification was needed for new implementations, yet each product felt distinct and purpose-built.

Atoms

Foundational building blocks designed for desktop applications:

  • Color tokens and typography scales
  • Button states and variants
  • Input fields and form controls
  • Icons and iconography system
  • Spacing and layout primitives

Molecules

Reusable component combinations with built-in flexibility:

  • Search bars with filters
  • Form field groups with validation
  • Card structures and containers
  • Navigation menu components
  • Alert and notification patterns

Organisms

Complex, application-ready UI sections:

  • Data tables with sorting/filtering
  • Navigation headers and sidebars
  • Account selection interfaces
  • Multi-step form workflows
  • Dashboard widget layouts

Atoms: Foundation Layer

Created the fundamental building blocks optimized for desktop financial applications. Each atom was designed with flexibility in mind, supporting multiple states, themes, and contexts without requiring redesign.

Core atoms: buttons, inputs, icons, typography, and color tokens with all state variations

Design Solution

Established a core library of atomic elements including buttons in 5 sizes, input fields with 8 validation states, and a complete icon system with 4 size variants. Each atom includes accessibility features, theming tokens, and clear usage guidelines. These atoms serve as the DNA for all higher-level components, ensuring consistency while enabling customization.

Molecules: Functional Components

Combined atoms into reusable molecules that handle common interaction patterns. These components maintain consistency across applications while allowing for contextual modifications through theming and configuration.

Molecule components: dropdowns, search bars, button groups, form field combinations, and card structures

Dropdown Systems

Created 15+ dropdown molecule variants combining input atoms, icon atoms, and list atoms. Each variant handles different complexity levels from simple selection to advanced filtering, all built from the same foundational components.

Button Groups

Designed flexible button molecule patterns that combine primary, secondary, and icon button atoms. These molecules adapt to different contexts like toolbars, forms, and action panels while maintaining consistent spacing and hierarchy.

Organisms: Complex Patterns

Built sophisticated organisms by combining molecules and atoms into complete, functional UI sections. These organisms provide application teams with ready-to-use patterns while remaining customizable for unique requirements.

Complex organism patterns: navigation headers, data tables, account cards, form wizards, and dashboard layouts

  • Account selection organisms using card molecules, button atoms, and typography tokens
  • Navigation header organisms combining search molecules, icon buttons, and dropdown menus
  • Data table organisms with filter molecules, pagination, and action button groups
  • Form wizard organisms utilizing progress molecules, input field groups, and navigation buttons
  • Dashboard card organisms combining various molecules for metrics, charts, and quick actions

Scalability Benefits

This atomic approach meant that when building a new application, teams could start with established organisms, swap in application-specific molecules where needed, or even just modify atoms for subtle branding differences. A single organism could serve 5 different applications with only color token changes, or be heavily customized by replacing key molecules while maintaining the core interaction patterns.

Cross-Application Flexibility

The atomic structure enabled each application to maintain its unique character while sharing the same design foundation. Teams could quickly assemble interfaces using pre-built components, then customize through theming, configuration, or selective molecule replacement.

Teams now ship features 70% faster using the atomic component library. Design consistency scores improved from 45% to 94% across applications, even as each maintained distinct identities. New designer onboarding reduced from 3 months to 2 weeks thanks to clear component hierarchy. Accessibility compliance increased to 100% across all products, with atoms handling WCAG requirements at the foundational level.

Lessons Learned

Building a design system using atomic principles taught us as much about organizational change as it did about component architecture.

What Worked

• Starting with atoms forced clear thinking about fundamentals

• Desktop-first approach matched our primary use cases

• Modular architecture enabled application uniqueness

• Clear hierarchy made the system easy to learn and extend

What We'd Change

• Should have documented composition patterns earlier

• Needed more guidance on when to customize vs. use defaults

• Mobile organism variants came too late in the process

• Governance model for adding new atoms needed day-one clarity
